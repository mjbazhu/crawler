# 智能体读取与执行索引

本目录是 Crawler 智能体的专用工作说明。根 [AGENTS.md](../../AGENTS.md) 提供入口；这里说明怎样识别任务、定位代码、执行验证和交接，项目知识正文从 [项目文档索引](../README.md) 引用。

## 开始任务怎么读

1. 先确认用户要分析、审查、修复还是新增能力，核对工作目录、Git 分支和已有修改。
2. 打开 [任务分类指南](task-routing.md) 的“快速分类”，选一个主类；按症状与调用链补充关联类别，再读该类的具体步骤。
3. 修改代码时读 [开发规范](development.md) 的 C++20、错误处理及相关专项章节，并按任务指南定位项目资料和首查代码。
4. 从 [验证要求](validation.md) 选择对应 target 和环境类型；读源码、编译成功和测试通过分别记录。
5. 接续旧任务时读 [当前交接](current.md)，核对其中的分支、提交、文件和验证状态；提交等 Git 操作前读 [Git 流程](git-workflow.md)。

只读取当前类别和必要的关联章节；已读且未变化的规范不重复加载。分类说明需要显式读取，不依赖链接自动展开。

## 文件职责

| 文件 | 解决什么问题 | 读取时机 |
| --- | --- | --- |
| [task-routing.md](task-routing.md) | 任务怎么分类，首查哪些代码，怎样处理、联动及验收 | 开始任务、范围变化、陌生故障或新增能力时 |
| [development.md](development.md) | 实施时遵守哪些编码、分层、错误、存储、HTTP 和并发约束 | 修改或审查相关代码时；外部检索只读检索章节 |
| [validation.md](validation.md) | 哪些 target 对应本次改动，需要什么环境，怎样记录结果 | 选择验证方案、执行测试、审查和交付前 |
| [git-workflow.md](git-workflow.md) | 怎样暂存、提交、推送及合并，哪些步骤需确认 | 执行相应 Git 操作前 |
| [current.md](current.md) | 当前具体任务做到哪里，哪些修改和验证需要接续 | 新会话接续或任务需要交接时 |

仅整理文档时，读取待修改文件及验证要求的“仅整理说明文档”；不触发 C++ 编译。只读审查按任务指南的“代码审查”执行。构建配置、运行排障和开发任务的入口均在任务指南中，索引不重复维护第二张分类表。

## 分类与交接的维护要求

- 每个任务类别必须包含识别条件、必读范围、首查代码、处理步骤、联动修改、验证和完成标准；文件链接是查找起点，不是每次都要修改的清单。
- 新增类别先确认现有类别不能覆盖；只在本目录维护智能体专用说明，不把架构或业务正文复制进来。
- 任务指南中的代码路径、符号和测试 target 改名时同步更新引用；以实际源码与 CMake 注册结果核对，不根据类名猜文件名。
- 根入口保留核心约束和导航，建议不超过 8 KiB；详细分类只在任务指南维护。
- 需要交接时更新当前目标、分支与基线、已有修改、本轮修改、实际验证、未完成事项和下一步；替换过期状态，不追加聊天全文。
- 重写 `current.md` 前，按 [项目文档维护边界](../README.md#维护与专题边界) 保留需长期引用的结论和证据入口；交接通过链接引用，避免唯一一份验收结论随任务覆盖。歌手资料任务的历史结果见 [长期验收记录](../migu/singer-profile-validation.md)。
- 实测结果注明日期、版本、条件及脱敏证据位置；链接有效、编译完成和历史成功率不能写成本次业务回归通过。
