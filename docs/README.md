## 推荐阅读顺序

- 初次了解模块：先看架构的运行结构和模块范围，再按工作内容选择元数据、SQL 或资源流程。
- 对接接口：定位 API 说明及 OpenAPI 中的相关路由和 schema，再核对该业务的字段、计数及状态语义。
- 修改并验证：先选对应业务资料，再按现有测试分类确定环境与 target；构建、静态检查、测试执行和真实平台验证分别报告。
- 排查资源运行：结合批次事件、资源流程、实际启动配置与运行说明定位阶段；本机路径和历史实验需按当前环境核对。

## 当前覆盖与已知差异

目前已经具备架构、核心业务、API、SQL、事件和智能体执行说明；测试分类与 target 映射也已补齐。完整的从零启动、配置说明及通用服务恢复指南仍待编写。

- [API 资源处理说明](api/mg/migu-api.md#资源下载处理) 仍描述可选自动百度上传，而 [当前组合根](../src/infrastructure/app/ServerApplication.cpp) 明确关闭该功能，需要校准。
- API 说明、静态 OpenAPI 和运行期 `GET /api/openapi.json` 需对受影响契约逐项核对；兼容协议字段、临时传输字段与实际落库字段的职责分别确认。
- 现有运行说明包含本机路径、外部对账脚本和历史实验背景，尚不能直接视作其他环境的部署手册。
- 历史成功率和上传实验缺少完整的日期、提交及原始日志信息，引用时保留证据边界；新的运行结论需要对应环境的实际验证。
