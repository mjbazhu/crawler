更新日期：2026-10-27。代码核对基线：`f48011bb69fe93d7368d3043bd7da105948949d0`，工作区另有尚未提交的文档整理。

目标是让音乐数据获取、解析与存储有一致的说明、可复现的运行方式和可验证的可靠性。本页维护后续工作的范围、依赖、验收和状态；当前结构与约束见 [架构](../architecture/README.md)，文档入口与缺口见 [总索引](../README.md)。

## 当前基线

- 已具备模块分层、元数据关系、资源流程、API/OpenAPI、表级 SQL 和批次事件说明；总索引已记录覆盖范围与缺口。
- 已具备智能体任务分类及按改动选择测试的 [执行指南](../agents/task-routing.md) 和 [验证要求](../agents/validation.md)，包括离线、本机 I/O、独立 MySQL、真实平台四类条件。
- 当前装配默认使用 MySQL，SQLite 保留显式调试兼容后端；依据为 [应用配置](../../include/crawler/infrastructure/app/ServerApplication.h) 和 [持久化装配](../../src/infrastructure/app/PersistenceAssembly.cpp)。
- 已确认 [资源 API 说明](../api/mg/migu-api.md#资源下载处理) 的可选自动百度上传描述与 [组合根](../../src/infrastructure/app/ServerApplication.cpp) 关闭该功能的现状不一致，需要在 M1 校准。
- 完整快速启动、统一配置说明和通用服务恢复指南尚未建立。已有本机操作记录及历史成功率不能替代当前环境的验收证据。

## M1 现状校准

**目标**：先让维护者看到的接口、字段职责和状态语义与当前实现一致。首批范围是资源处理、歌手/专辑计数和相关查询契约。

**前置条件**：能够读取当前代码、API 说明、静态 OpenAPI 与相关 SQL；离线 API 检查使用已配置的构建环境。

| 工作项 | 推进内容 | 交付物 |
| --- | --- | --- |
| M1-1 资源处理契约 | 核对当前装配、兼容 uploader 分支、手动上传/对账结果；修正自动上传描述，确认受影响字段的实际用途 | 校准后的资源 API 说明、相关 schema 解释和测试断言 |
| M1-2 字段与状态口径 | 对照 [元数据模型](../migu/metadata.md) 与 [MySQL 表职责](../../sql/mysql/README.md)，核对来源身份、真实关系计数、同步计数及永久跳过语义 | 受影响接口、业务说明和查询语义一致，差异有处理结论 |
| M1-3 契约一致性核对 | 比较 [API 说明](../api/mg/migu-api.md)、[静态 OpenAPI](../api/mg/openapi-migu.yaml) 和 [运行期文档生成](../../src/api/controllers/OpenApiDocumentFactory.cpp) 的受影响 path/schema；按需要补充自动检查 | 明确的核对范围、差异清单、最终结果及可复用检查 |

**验收标准**：首批范围的差异均已修正或形成明确兼容说明；API 类回归按实际影响执行；静态 YAML 与运行期契约的受影响部分完成核对。协议兼容字段、临时传输字段和持久化字段分别确认用途，不能因数据库删列直接推导协议删字段。

**证据与状态**：记录实际修改文件、核对路由、测试命令及结果。单纯更新说明但尚未完成相应核对时标为待验收；历史测试记录不计作本阶段证据。

## M2 运行闭环

**目标**：新接手者能够按说明完成配置、构建、启动、健康检查和最小查询，并知道设置从哪里读取和何时生效。

**前置条件**：明确当前默认装配及受影响契约；首个目标环境沿用现有 Windows/MSVC、Ninja 与 vcpkg preset。实际启动验证具备独立测试库及可用配置。

| 工作项 | 推进内容 | 交付物 |
| --- | --- | --- |
| M2-1 快速启动 | 串联工具链准备、preset 路径调整、工作目录、测试库与 migration、构建、启动/停止和最小调用 | 拟新增 `docs/getting-started.md` |
| M2-2 配置说明 | 汇总环境文件选择、覆盖顺序、默认值、启动选项、热更新策略、只读快照及兼容/停用项；说明 MySQL 与 SQLite 调试模式的能力差异 | 拟新增 `docs/configuration.md`，并引用实际配置来源 |
| M2-3 按文档演练 | 从指南声明的起点执行步骤，核对 `GET /api/health`、`GET /api/migu/settings` 和一项离线检查；修正遗漏条件 | 带环境、代码版本、命令、预期与实际结果的演练记录 |

**验收标准**：按指南完成目标环境的构建、服务启动/停止、健康检查和最小查询；默认值、覆盖顺序及生效时机与实际消费者一致。说明中区分本机示例路径与通用要求，示例不包含真实密钥或 token。

**证据与状态**：配置和命令来源见 [启动入口](../../src/main.cpp)、[应用配置](../../include/crawler/infrastructure/app/ServerApplication.h)、[preset](../../CMakePresets.json) 和 [配置示例](../../.env.example)。指南已写但尚未走通时标为待验收，缺失环境如实记录。

## M3 可靠性验收

**目标**：验证既有采集入库与资源管线的可靠性，明确取消、失败和恢复路径，并把实际可执行的操作整理成维护说明。

**前置条件**：相关契约已校准，目标运行环境可用；MySQL 检查确认有效配置指向独立测试库，真实平台检查具备相应授权和条件。

| 工作项 | 推进内容 | 交付物 |
| --- | --- | --- |
| M3-1 元数据与迁移 | 验证身份/关系幂等、字段合并、事实计数、事务失败及封面回滚、历史结构升级、重跑和 SQL prepare | 对应离线与独立 MySQL 场景的验证结果，发现的缺陷及修复记录 |
| M3-2 资源与任务 | 验证完整提交后回写、下载失败清理、临时 URL 重取、永久跳过保护、取消/超时、重复认领及终态一致性 | 场景、预期状态、对应测试、实际结果与未覆盖项的验收矩阵 |
| M3-3 服务运行与恢复 | 整理启动/停止、stale 任务恢复、迁移失败定位、备份/恢复和资源对账的适用条件及操作后检查 | 拟新增 `docs/operations/service-lifecycle.md`；本机资源说明继续引用原文 |
| M3-4 证据收口 | 补充必要的数据流及状态迁移说明，为运行记录标注日期、代码版本、环境、范围和脱敏证据位置 | 当前有效的验收结论及剩余限制，实际文档中的证据入口 |

**验收标准**：受影响场景有可复现输入、预期状态和实际验证，失败与恢复路径有结果；运行指南明确区分应用回滚、迁移修复及备份恢复。按 [验证分类与 target 映射](../agents/validation.md#按任务选择验证) 选择检查，不能用一个异步调度测试替代全部任务业务回归。

**证据与状态**：离线、本机 I/O、独立 MySQL 和真实平台结果分别记录。真实平台未验证时保留该限制；已交付但仍缺必需验证或有效证据的工作项标为待验收，不以旧成功率补足。

## M4 按证据演进

**目标**：依据已经证实的瓶颈或维护成本推进局部改进，保持采集、解析和可靠存储的模块边界。

**前置条件**：每个候选先形成问题描述、基线、目标、影响范围及可运行的回归方案；实施前确认相关可靠性检查能够覆盖行为变化。

| 候选方向 | 进入条件 | 完成标准 |
| --- | --- | --- |
| 兼容入口与职责收敛 | deprecated 构造、聚合接口或兼容门面确实阻碍当前变更；调用者与替代路径已摸清 | 已确认的调用者完成迁移，相关回归通过，职责边界和兼容影响有说明 |
| 查询、网络或资源管线优化 | 运行证据指向具体 SQL、I/O、并发调度或存储瓶颈，并给出可重复测量的基线 | 同一条件下达到专项确定的目标，失败率、幂等、回滚和状态语义未退化 |

**交付物**：有明确问题和验收目标的独立改进项、必要代码/文档、前后对比与回归证据；候选仅在条件满足时转为实施事项。

**验收标准**：收益和代价有证据，保留现有分层与窄 port 边界；接口拆分或新基础设施由实际问题和替换点支撑。当前没有为这些候选设定实施排期。

| 状态 | 使用条件 |
| --- | --- |
| 待推进 | 范围已明确，工作尚未进入实施 |

## 路线怎样拆分和维护

- 当前仅维护本页总路线。架构文档继续说明现状与约束，总索引继续维护资料入口与文档缺口，智能体交接只记录当前任务进展。
- 多个专项能够独立推进和验收，或某一项需要较多执行细节时，再在本目录建立有实际内容的专项文件；例如可靠性验收或已有基线的性能改进。总路线保留推进顺序、里程碑和专项链接。
- 专项文件记录具体场景、实施步骤、前置条件和证据，总路线引用其细节；文档缺口表、target 清单和接口正文沿用现有入口，保持单一维护来源。
- 范围、交付物或实际依赖变化时更新路线与总索引；新增文件存在后才建立链接，尚未交付的文件名以拟新增项记录。
